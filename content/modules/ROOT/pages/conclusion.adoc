[[key-takeaways]]
== Key Takeaways

* *Place the workload yourself* -- RHACM puts virtual machines, clusters, and applications on the clusters you choose. OpenShift Lightspeed is the hands-off alternative for that placement.
* *Keep AI on the platform* -- OpenShift AI runs the workload where the data already lives.
* *Guardrails limit the attack surface* -- RHACS shows the vulnerability and the runtime behavior, then enforces the policy. RHACM policy keeps a region in bounds.
* *Identity is the next control* -- Red Hat Zero Trust Workload Identity Manager (ZTWIM) is how containers, virtual machines, and AI applications get multi-factor, keyless access to systems and data.
* *The image you run should be one you signed* -- a golden base image in Quay, signed with Trusted Artifact Signer, stays inside the platform you manage.

[[next-steps]]
== Next steps

* Use OpenShift Lightspeed when you want the same placement work done for you
* Add ZTWIM so each workload authenticates to the systems and data it is allowed to reach
* Expand the RHACS profiles and RHACM policies for the regulations you operate under
* Keep signing the images that land on the clusters
